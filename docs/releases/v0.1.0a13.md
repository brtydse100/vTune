# v0.1.0a13 - Software trust release candidate

Released September 4, 2026. Install the inspection and reporting tools with
`pip install "vllm-optimizer==0.1.0a13"`, or add the Linux/WSL experiment
runtime with `pip install "vllm-optimizer[runtime]==0.1.0a13"`.

This alpha aligns optimization with reporting, makes measurement evidence more
honest, closes secret-handling gaps, and makes coordinator failures recoverable.

## Search and scoring

- The configured maximize metric is the primary objective among eligible
  trials from search through terminal, JSON, CSV, and HTML output.
- The configured request-failure percentage remains a hard eligibility gate.
- Failure percentage and failure count provide deterministic tie-breakers.
- Baseline comparison and per-benchmark rankings use the same selected winner.

## Measurement confidence

- Trusted defaults are one warmup and three measured repeats, with three
  successful repeats required for ranking.
- Explicit one- and two-repeat smoke configurations remain valid and are
  labelled exploratory in reports.
- Confidence intervals use a small-sample Student's t calculation instead of
  presenting a single observation as statistically dependable.
- Reports state when confidence or drift detection lacks enough measurements.

## Secrets and reproducibility

- Nested mappings and lists are recursively redacted in manifests, normalized
  results, reports, terminal output, arguments, headers, and environment data.
- Conventional credential, authorization, cookie, access-key, client-secret,
  password, and token names are recognized, including `--option=value` forms.
- Redaction affects display and persistence only; subprocess commands retain
  their actual configured values.
- Effective repeat, warmup, drift, and request-failure policies are stored in
  run results and reused by offline regeneration and reclassification.

## Lifecycle and offline behavior

- Coordinator failures atomically finalize runs as `failed`, preserve completed
  trials, sanitize the recorded failure, set completion time, and close terminal
  resources.
- Task cancellation and keyboard interruption finalize runs as `interrupted`.
- Offline reporting validates stored evidence and leaves source runs immutable.
- Legacy reports reconstruct compatible benchmark policy from their manifests.

## Contributor and release gates

- Added deterministic Ruff, formatting, mypy, pytest, and coverage settings.
- Added synthetic integration and fault-injection coverage for scheduling,
  search, retries, processes, CLI behavior, reporting, and run finalization.
- CI tests Python 3.11 and 3.12 using non-editable installations and clean
  wheels; Python 3.12 owns the deterministic risk-focused coverage gate.
- Publication requires tests, coverage, lint, types, strict documentation,
  dependency audit, SBOM, package validation, version consistency, and matching
  private-regression evidence.
- Production modules were split by responsibility and remain at or below 150
  lines.

## Validation

- The combined public and available private suites passed: 152 tests and 12
  subtests.
- Python 3.11 and 3.12 package workflows passed, including clean wheel tests.
- Repository coverage was 84%; all 34 risk-focused module thresholds passed on
  the designated coverage job.
- Ruff, formatting, Linux and Windows mypy checks, strict documentation, Twine,
  `pip check`, dependency audit, and archive inspection passed.

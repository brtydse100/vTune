# v0.1.0a12 - Live benchmark observability and failure policy

Released September 2, 2026.

## Live execution

- Benchmark output is flushed into `benchmark.log` while the subprocess runs.
- Request-limited workloads show completed requests; duration-limited workloads
  show an elapsed timer.
- Fast workloads append their exact final count even when metric polling misses
  the final requests.
- Trial headings use a brighter terminal color.

## Request quality and reports

- `benchmark.max_failure_percentage` accepts a bounded error percentage.
- `benchmark.accept_any_request_failures` ignores the percentage while still
  requiring a successful request and usable metric.
- JSON, CSV, and HTML show successful, failed, errored, and incomplete requests
  and failure percentage for each benchmark repeat.
- Backend-provided failed request details are stored in `failed_requests.json`.

## Offline reclassification

`vllm-opt reclassify` reads stored benchmark evidence and creates new JSON, CSV,
and HTML outputs under a different failure policy without starting a server or
benchmark process. The source run remains immutable.

## Validation

The release was exercised in WSL2 on an NVIDIA RTX 3080 with two real repeats
of both GuideLLM 0.7.3 and vLLM Bench Serve. Both backends completed 10 of 10
requests successfully, and their outputs were normalized into consistent
per-repeat JSON, CSV, and HTML results. The successful vLLM smoke used the
installed vLLM 0.19.0 V0 engine because vLLM 0.28.0 could not start in this WSL
environment when unified virtual addressing was reported unavailable. Native
Linux vLLM 0.28.0 GPU validation remains outstanding.
